1. Document Overview
This document describes the complete chatbot conversation flow implemented for Samriddhi 
Anveshana (SA). It covers every message a user can receive, every question the bot asks, and what 
information is collected at each step. This is designed to work across WhatsApp, Telegram, and Arattai 
platforms.
1.1 Purpose
•Define the full conversation structure from first touch to final handoff
•Serve as a reference for developers integrating the flow into Flask + PostgreSQL
•Act as a guide for team members managing or updating the bot

9. Data Stored in PostgreSQL
Every conversation interaction is saved to the database. Below is what gets stored and why.
9.1 Users Table
Column Type Purpose
id Auto number Unique identifier for each user
phone Text Phone number (WhatsApp), Chat ID (Telegram), User ID 
(Arattai)
platform Text Which platform the user came from
created_at Timestamp When the user first contacted SA
9.2 Messages Table
Column Type Purpose
id Auto number Unique message record ID
user_id Reference Links message to the user who sent it
message Text The exact text the user typed
response Text The exact reply the bot sent back
platform Text WhatsApp / Telegram / Arattai
created_at Timestamp Time the message was sent

11. Key Implementation Notes
•All conversations start from a single entry message — same across WhatsApp, Telegram, and 
Arattai
•User replies with a number (1-5) to navigate — no free text needed at menu steps
•Each service collects exactly 6 data points from the user before ending
•All conversations end with the same final thank you message regardless of path
•Every message and reply is saved in PostgreSQL for analytics and follow-up
•The SA operations team receives the lead data and follows up manually or through CRM
•Contact number is always the last question collected — ensuring maximum engagement before 
asking for personal info
